# Documentation agent instructions

These instructions apply to the Mintlify agent and to any coding agent editing this site. Repository
layout and sync rules are in `/AGENTS.md`.

## Project context

- docs.kalarislabs.com is the documentation hub for Kalaris Labs open-source projects. Each project is a
  Mintlify product in `docs.json` with its own directory: `research-agent-skills/`, `skill-doctor/`.
- Readers are researchers, students and engineers using AI coding agents (Claude Code, Codex, Cursor,
  Gemini CLI, GitHub Copilot, OpenCode, Windsurf).
- `research-agent-skills/` is generated by a sync from `KalarisLabs/research-agent-skills/docs`. Never edit
  it here; propose the change in that repository instead.

## Style

- Second person, active voice, plain language. Lead with what the reader can do.
- Sentence case for headings, card titles and code block titles.
- No marketing words ("powerful", "seamless", "robust", "cutting-edge") and no filler ("simply", "just",
  "in order to", "it's important to note").
- Write "Kalaris Labs", "Research Agent Skills" and "Skill Doctor" exactly like that.
- Every claim about behavior, flags or numbers must come from the project's source or README. Mark
  anything unverified with `{/* TODO: verify */}` rather than guessing.

## Page structure

- Frontmatter: `title` (specific, searchable), `description` (one or two sentences for SEO), and a short
  `sidebarTitle` when the title is long.
- Overview pages: one-paragraph summary, a single install or run command, then cards to next steps.
- Guides: prerequisites first, then `<Steps>`, then a "Next steps" section.
- Reference pages: tables or `<ResponseField>` for flags and options; exit codes as a table.

## Components

- Cards go in `<Columns cols={2}>` or `<Columns cols={3}>`.
- Use `<Tabs>` when the reader picks one option (npm vs cargo, Claude Code vs Cursor).
- Use `<CodeGroup>` for the same action in several forms.
- Callouts: `<Note>` for side information, `<Tip>` for recommendations, `<Warning>` for anything that can
  break or cost data. Do not stack callouts.
- Icons use the Lucide library (`flask-conical`, not `flask`). Check a name exists before using it.

## Code and links

- Every code block has a language tag; config examples also have a filename title (```json mcp.json).
- Use real package names and commands, never `foo` or placeholder flags.
- Internal links are root-relative without extensions: `/skill-doctor/reference/cli`.
- Images need descriptive alt text. Store project images in `<project>/assets/`, site images in `/images/`.

## Before you finish

- Add new pages to the right product and group in `docs.json`.
- Run `mint broken-links`, `mint validate` and `mint a11y`.
